    Plan: writing with nanom (Parquet first, Lance later)¶

    nanom describes a binary layout once (describe<T>, field<Id, T>, be<>, ubits<>), and that description can drive writing as well as reading. This plan turns the write side into production code, in the spirit of Rust's deku / binrw (derive read + write from one description) and cookie-factory (serializer combinators over a sink). The first user is nanoarrow2parquet; Lance comes later.

    Rule zero: reading stays exactly as it is. Encoders live in their own headers that the read path never includes, so a reader's code, compile time and speed do not change. See Reading only.

    Why¶

    • One description, no drift. Field ids, types, required / optional and enum values exist once. Before this plan, nanoarrow2parquet carried its own 156-line Thrift encoder and built FileMetaData with hard-coded field numbers: a second copy of nanom/formats/parquet_thrift.hpp that nothing kept in sync.
    • Much stronger tests in both directions. Every encoder is checked by a round trip through decoders already proven against pyarrow. Every decoder can be fed structurally valid inputs generated by encoding random values, which reaches far deeper than random bytes.
    • Lance fits the same model. Lance metadata is protobuf: tagged like Thrift. A protobuf wire codec next to the Thrift one lets one field<Id, T> description serve both.

    Design rules¶

    • Two-way comes from described types, not from combinators. Combinators such as alt, take_while, Thrift skip-on-mismatch or lenient size checks lose information and cannot be inverted. Parsers stay one-way; described types (field<>, list<>, lazy<>, be<>, ubits<>) are two-way.
    • Sinks, not containers. Encoders write to a byte sink: a growable vector, a fixed span (overflow is an error, never a write past the end), a counter (exact size without writing) or any type with bool put(const std::byte*, std::size_t) (a file, a socket). Small writes are staged; large payloads pass straight through.
    • Zero-copy writing. Strings and binaries are views. Repeated members are written from a caller's span (list<E>::of(span)) and nested messages from a caller's object (lazy<M>::of(m)) without copying. Lists and structs decoded from a file are written back verbatim.
    • Writing is checked like reading. A length or count that does not fit the wire type (a Thrift i32) is an error. A required nested message that was never set is an error. An overflowing fixed sink is an error. The encoder reports where (describe<M>::name()).
    • Policy stays in the writer. Page sizes, dictionary fallback and statistics are decisions; nanom supplies the codecs and kernels.

    Phases¶

    phase work done when status
    A Production Thrift compact encoder: nanom/tagged_encode.hpp with sinks, exact size, list<E>::of / lazy<M>::of sources, narrowing and required-message checks. nanoarrow2parquet encodes PageHeader / FileMetaData from the shared parquet_thrift.hpp model and drops its hand-written encoder. Files round-trip through pyarrow, arrow-rs and parquet2nanoarrow; footers read back identically by all three; write speed at parity with the previous nanoarrow2parquet. done (results)
    B emit<T> for fixed-layout described structs (be<>, ubits<>, arrays), with computed fields (lengths, counts, offsets filled by a size pass or back-patch, like binrw's calc). Every described type in nanom's tests and examples round-trips byte-for-byte. done (results)
    C Encoding kernels next to the decoders: bit packing, RLE / bit-packed hybrid, DELTA_BINARY_PACKED, BYTE_STREAM_SPLIT, a dictionary builder, statistics; possibly Snappy / LZ4 compression (zstd stays external). Each kernel round-trips through its decoder and is fuzzed; nanoarrow2parquet gains the encodings it lacks. done (results); Snappy / LZ4 compression not needed yet
    D nanoarrow2parquet rebuilt on A–C. A protobuf wire codec on the same field<Id, T> model for Lance metadata; nanolance (the Lance writer) moved onto it. Parquet and Lance writing on one base, checked by their reference readers. done (results): nanoarrow2parquet runs on A–C since phase C; Lance metadata through nanom

    Phase A in detail¶

    nanom

    1. nanom/tagged_encode.hpp (new; tagged.hpp does not include it):
    2. sinks: vector_sink, span_sink, counting_sink, and any byte_sink;
    3. thrift_compact_encode(m, sink) -> expected<std::size_t, encode_error>;
    4. thrift_compact_size(m) (exact, via the counting sink);
    5. checks: string, binary and list lengths must fit i32; a required lazy<M> must be set.
    6. list<E>::of(std::span<const E>) and lazy<M>::of(const M&) in tagged.hpp: borrowed sources that iterate and decode like decoded ones, so code that inspects a model works on both.

    nanoarrow2parquet

    1. Depend on nanom (pinned, header-only). Page headers and the footer are built as nanom_formats::parquet structs and encoded with nanom. src/thrift_compact.hpp is deleted. Page headers encode into a stack buffer (span_sink), so the per-page cost does not grow.

    Testing, built during the work (not after it)

    • Round-trip property tests (nanom): random values of every Parquet model message, with random optional fields, strings and lists, are encoded, decoded and compared field by field. Re-encoding what was decoded must give identical bytes.
    • Size and sink properties (nanom): thrift_compact_size equals the bytes written. Encoding into every too-small span_sink fails without writing past it, checked under ASan with exact-size buffers.
    • Structured fuzzing (nanom): the Thrift fuzzer also encodes random messages, mutates the bytes and decodes them. Valid inputs must decode to the same value; mutated ones must fail cleanly.
    • External oracles (nanoarrow2parquet): every written file is read by pyarrow, by arrow-rs (the Rust parquet crate) and by parquet2nanoarrow. Data must equal the input. Footer fields (schema, row groups, chunk offsets and sizes, encodings, codec, created_by) must agree across all three and with what was written.
    • Performance: the nanoarrow2parquet write benchmark before and after, on the same host.

    Phase B results¶

    nanom/emit.hpp writes fixed-layout described structs, the inverse of strct<T>() and overlay<T>(). The byte sinks moved to nanom/sink.hpp, which both encoders share.

    auto bytes = nm::to_bytes(hdr);                     // std::array<std::byte, wire_size_v<T>>, constexpr
auto n     = nm::emit(hdr, out_span);               // into a buffer, never written past
auto m     = nm::emit_frame(hdr, payload, sink);    // header + payload (passed through, no copy)

template <> struct nm::computed<ipv4_hdr> {        // binrw-style computed fields
  static constexpr auto fields = std::tuple{
      nm::calc<"total_len">([](const ipv4_hdr&, const nm::emit_ctx& c) { return 20 + c.payload.size(); }),
      nm::checksum<"checksum">([](std::span<const std::byte> h, const nm::emit_ctx&) { return csum(h); }),
  };
};
bool ok = nm::verify_computed<ipv4_hdr>(received, nm::emit_ctx{payload});   // the read side
    • Exact inverse. be / le fields keep their wire bytes; plain scalars use the same default byte order as strct; bit fields are written with the exact inverse of read_bits (msb0 and lsb0); arrays and nested structs recurse.
    • Computed fields. Field names are checked at compile time (calc<"lenght"> does not compile). calc runs before encoding and checksum runs over the encoded bytes with its field zeroed. Results are range-checked into their field: a payload too long for a be<u16> length is an encode_error naming the field, never a truncated value.
    • Range checks. A ubits<N> / ibits<N> value outside N bits is an error too. The reader always masks; the writer refuses.
    • A read-side bug fixed on the way. The bit-field docs said msb0 and lsb0 fields "may be mixed field-by-field", but when they shared a byte read_bits read the same bits for both, so one field silently got the other's value. layout_ok now rejects a byte holding bits of both orders, at compile time, for reading and writing alike. No layout in nanom's tests or examples was affected.

    Phase C results¶

    nanom/columnar_encode.hpp holds the page encoders, each the inverse of a decoder (table in COLUMNAR.md). nanoarrow2parquet now uses them:

    • Levels and indices are real RLE / bit-packed hybrid streams. Before, everything was one long bit-packed run written a bit at a time. Definition levels of an optional field are encoded straight from its presence bitmap (a literal group is one bitmap byte), so no per-row level array is built.
    • Dictionary: nanom's open-addressing string_dictionary replaces std::unordered_map.
    • Statistics, new: every column chunk carries min / max / null count in Parquet's orders. Unsigned columns compare unsigned, floats follow the spec, binary compares as unsigned bytes, and the footer declares column_orders. min / max come from the typed Arrow buffers, or from the dictionary's distinct values (the same answer without comparing each row).
    • Encodings, new: n2p_writer_set_encoding() selects AUTO (the previous behaviour), PLAIN, DELTA (DELTA_BINARY_PACKED for integers, DELTA_BYTE_ARRAY for strings) or BYTE_STREAM_SPLIT (floats).

    Correctness

    check result
    nanom test_columnar_encode every encoder through its decoder over random data at every width: run-heavy, noisy, constant and extreme values, empty and one-value inputs, keys of every length 0..80 in exact-size buffers. Planted bugs in the RLE run-stealing and in a DELTA miniblock width are caught (1,836 and 1,150 failures).
    nanom fuzz_columnar_encode 300,000 iterations clean under ASan / UBSan. It found an out-of-bounds read in the first version of the dictionary hash (keys of 17–23 bytes), fixed before anything shipped.
    oracle_roundtrip (nanoarrow2parquet) 49 files: the 8 table shapes x {zstd, uncompressed} x {AUTO, PLAIN, DELTA, BYTE_STREAM_SPLIT}, plus the empty file. They read back exactly in pyarrow, arrow-rs and parquet2nanoarrow. Statistics of every row group and leaf match min / max / null count computed independently in Python. Also clean with the writer built under ASan / UBSan. Turning off unsigned ordering in the statistics produces 96 failures.

    The first build of this phase was slower on string-heavy and many-row-group cases (0.82–0.94x). Two things fixed it: computing string min / max from the dictionary instead of comparing every row, and a hash for short keys (two overlapping word loads, one multiply-mix) instead of the FNV-style loop.

    Phase D results¶

    Parquet was already on A–C after phase C. Phase D added protobuf and moved Lance's metadata onto it.

    nanom. New headers: - nanom/protobuf.hpp reads protobuf. - nanom/protobuf_encode.hpp writes canonical proto3. - nanom/formats/lance_protobuf.hpp declares Lance's Manifest, DataFragment, DataFile, DeletionFile, Field, Schema, FileDescriptor, Metadata and ColumnMetadata / Page / Encoding.

    The structs are the same field<Id, T> ones the Thrift codec uses. Details are in PROTOBUF.md.

    nanolance. Its 808-line hand-written codec (generated/lance_minimal.pb.cpp) is now model conversions over nanom. The public header did not change. nanom is pinned and fetched headers only, and C++23 stays inside that one .cpp file: nanolance's API is still C++20.

    Correctness

    check result
    nanom test_protobuf (+ strict build) spec golden bytes, read rules, hostile input, encoder errors. Round-trip properties over messages generated by reflection, every Lance message included: decode(encode(x)) == x, a byte-identical re-encode, exact size, fixed buffers never overrun, every prefix rejected or read safely. A mutation run of 10 planted bugs found one untested case (a varint overflowing bit 63), now covered; one mutant is equivalent.
    protobuf_differential.py Google's protobuf runtime as oracle. nanom's encoding of 3,000 random Lance messages is byte-identical to protobuf's serialization. 3,000 protobuf-built messages, with real map<> fields and unpacked repeated fields, decode and re-encode equal. Truncations are accepted or rejected exactly as protobuf does. Planted bugs fail it (821 and 27 failures).
    fuzz_protobuf generated and mutated messages, canonical round trip, clean under ASan / UBSan; also a libFuzzer target.
    nanolance ctest 53 of 53 pass, including the pylance 12.0.0 interop tests.
    old vs new nanolance codec Both codecs compiled side by side on 20,000 random manifests, column metadata and data files. The new decoder reads the old encoder's bytes exactly as the old decoder did. The old decoder reads the new bytes as it reads its own. Only difference: an empty metadata key is now omitted, as prost omits it.
    bug found The hand-written encoder never wrote DataFragment.deletion_file. Every nanolance append to a dataset with deletions brought the deleted rows back (pylance read [1, 2, 3, 4, 5] after deleting 2). Fixed by the port, and guarded by a pylance smoke test that fails on the old build.

    Speed (nanolance, old codec vs nanom):

    benchmark old new speed
    encode manifest, 1,000 fragments x 50 columns (best of 7) 0.92 ms 0.77 ms 1.2x
    decode that manifest 0.95 ms 0.78 ms 1.15–1.25x
    decode a manifest the old encoder wrote (unpacked repeated) 0.95 ms 0.96–1.1 ms parity
    encode column metadata, 200 pages 94 µs 43 µs 2.2x
    decode column metadata 68 µs 54 µs 1.25x
    arrowipc2lance append to a 4,000-fragment dataset (tmpfs, median of 7) 12–15 ms 12.5–13.2 ms 0.92–1.16x (parity)
    arrowipc2lance create, 2M rows x 3 columns 223–257 ms 215–243 ms 0.97–1.07x (parity)

    The first port decoded column metadata at 0.90x and the old encoder's unpacked manifests at 0.55x. Three changes in nanom's reader closed the gap: - one-byte varints are read inline; - a run of unpacked records with the same key is read in one loop; - packed varint runs reserve their exact count (one value per byte without the continuation bit).

    Manifests are also smaller: 166 KB instead of 262 KB for the benchmark one, from packing and leaving out defaults.

    Reading only: the short path¶

    For code that only reads (and for AI assistants generating such code), include just what you need:

    task include entry points
    parse a binary layout nanom/nanom.hpp combinators, strct<T>(), overlay<T>()
    decode Thrift / tagged messages nanom/tagged.hpp thrift_compact<M>(), list<E>, lazy<M>
    decode protobuf nanom/protobuf.hpp protobuf<M>(), pb_sint<>, pb_fixed<>
    Lance manifests and file metadata nanom/formats/lance_protobuf.hpp protobuf<Manifest>(), protobuf<ColumnMetadata>()
    Parquet footer and page headers nanom/formats/parquet_thrift.hpp read_file_metadata, thrift_compact<PageHeader>()
    decode column pages nanom/columnar.hpp, nanom/values.hpp, nanom/codec.hpp see COLUMNAR.md

    None of these includes an encoder. Writing needs nanom/tagged_encode.hpp (Thrift), nanom/protobuf_encode.hpp (protobuf), nanom/emit.hpp (fixed-layout structs) and nanom/columnar_encode.hpp (column pages).
