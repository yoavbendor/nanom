2// nanom/formats/lance_protobuf.hpp — Lance's table and file metadata (protobuf) as reflected nanom
3// tagged messages.
4//
5// The shared model a Lance reader and writer (nanolance) build on: one declaration per protobuf
6// message, decoded by nanom/protobuf.hpp and encoded by nanom/protobuf_encode.hpp:
7//
8// auto m = nm::protobuf<lance::Manifest>()(nm::from(bytes)); // read
9// nm::protobuf_encode(manifest, out); // write
10//
11// Field numbers and types follow lance-format/lance's protos (lance-table table.proto, lance-file
12// file.proto / file2.proto / encodings). Only the fields nanolance reads or writes are declared;
13// everything else is skipped structurally on read, so newer writers stay readable. Enums are OPEN
14// (int32-backed): a value a newer writer added round-trips as its number.
15//
16// proto3 rules map to the model like this: implicit-presence fields are presence::defaulted (absent
17// = zero / empty, and a zero is not written), `optional` fields and message fields that may be
18// absent are std::optional, repeated fields are std::vector (scalars packed on write, both forms
19// accepted on read), and a map<K, V> is a std::vector of its {1: key, 2: value} entries.
20//
21// Zero-copy: strings and bytes are views into the decoded buffer (which must outlive them); for
22// writing they point at the caller's strings. Messages a writer must hand back intact when it
23// rewrites a manifest (Manifest, DataFragment, DataFile, DeletionFile, Field, IndexMetadata) keep
24// the fields they do not declare in a pb_unknown member.
